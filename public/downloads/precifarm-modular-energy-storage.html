20. Design moat

Precifarm does not need to manufacture every component.

Buy: LiFePO₄ cells · power electronics · inverter components · standard communication components · displays · connectors · protection components

Customize: Enclosures · mechanical architecture · Energy Modules · harnesses · thermal architecture · user interface · local installation architecture

Own: Energy OS · energy data · runtime algorithms · energy optimization · diagnostics · PAYGO platform · M-Pesa integration · customer account · service network · modular product architecture · customer energy experience

The objective is to build defensibility around the system and experience, not necessarily around commodity components.

1. Purpose

This document translates the Modular Energy Platform product vision into an engineering architecture Precifarm can prototype, certify and manufacture through partners.

It answers:

  • What is the common Energy Module electrical and mechanical interface?
  • How do P1 Go, P2 Home and Pod reuse that module without forking the BMS/CAN stack?
  • What do we buy, customize and own at the system level?
  • What safety, grid and Kenya regulatory envelopes apply?
  • What do Tesla and BYD teach — and what Precifarm should not copy?

1.1 In scope

  • Reference architecture, block diagrams, interface definitions
  • Target module specification (2.56 kWh LiFePO₄ class)
  • Power Core vs Energy Module separation (P2 / Pod)
  • Communications, Energy OS boundary, OTA and diagnostics
  • Thermal, protection, EMC and service architecture
  • Kenya installation classes (home plug-in vs fixed Pod)
  • Phased prototype → pilot → certification roadmap

1.2 Out of scope

  • Issued-for-construction wiring diagrams and protection coordination studies
  • Final cell supplier selection and UN38.3 / IEC 62619 test reports
  • Vehicle-side V2X hardware (referenced as future interface only)
  • Corridor DC hub design (see Solar Chargers & Stations)

2. Design motivation — Tesla and BYD (what to learn, what to reject)

Precifarm is not building a Tesla factory or a BYD gigafactory. The engineering goal is to import proven patterns into a Kenya-first, M-Pesa-native, modular home-energy line.

2.1 Tesla — system integration and the energy software layer

Tesla patternEngineering lesson for PrecifarmPrecifarm application
Powerwall — wall-mounted pack + integrated inverter/gateway; stackable capacity over timeSeparate energy from power conversion; customer adds kWh without replacing the inverterP2 Power Core fixed; Energy Modules stack under or beside
Megapack — repeatable 3 MWh blocks in a shipping-container form factorStandard module + repeated mechanical bay = factory and field scalabilityPod = N × identical Energy Modules in a serviceable rack
Energy segment economics — high-margin software + install network, not commodity cellsOwn Energy OS, diagnostics, PAYGO and service — not cell chemistryEnergy OS owns runtime prediction, module inventory, remote fault codes
Gateway / Powerwall Backup Switch — single customer-visible “energy brain”One app account, one telemetry schema across P1 → P2 → PodCommon device model in Energy OS; SKU-specific capability flags
NACS / open charging network (post-2023)Open interfaces where they create adoption; own experience where it creates retentionModule mechanical/electrical interface documented for internal SKUs first; public OEM licensing only if volume justifies
Over-the-air updatesField-fixable BMS parameters and inverter curves without truck roll for every bugSigned OTA to Power Core and Pod controller; module firmware pinned and versioned

Reject for Phase 1: proprietary vehicle lock-in, full vertical cell manufacturing, and marketing V2G before Kenya utility rules and bidirectional hardware exist.

2.2 BYD — modularity, LiFePO₄ and cost through repetition

BYD patternEngineering lesson for PrecifarmPrecifarm application
Blade Battery — long prismatic LiFePO₄ cells, cell-to-pack, structural rigidityOne cell format + one module footprint repeated across products reduces NRE and spare-parts SKU countStandard 2.56 kWh Energy Module built from one prismatic cell family
CTB / modular pack philosophyMinimize unique pack designs; maximize shared BMS firmware and CAN objectsSingle BMS application profile with product-specific limits (max charge C-rate, temp derating)
Vertical integration (~30% cost leverage at OEM scale)Precifarm integrates at enclosure, harness, thermal and software — buys cells and power stagesBOM strategy §8; local assembly partner for Pod racks
DM-i / range-bridge thinkingIn weak-grid markets, right-size storage + solar before oversizing inverter kWP2 base: 2.56 kWh / ~3–5 kW inverter class; expand kWh before kW unless load study says otherwise
Export via CKD / local assemblyPod rack + Power Unit suitable for Kenya SKD (cells imported, pack assembled locally when duty/logistics justify)Phase C: local module assembly line tied to KEBS/UN38.3 batch testing

Reject for Phase 1: claiming Blade-equivalent cell IP, owning prismatic cell R&D, or sizing Pod arrays without per-site load and export-limit studies.

2.3 Synthesis — the Precifarm engineering thesis

TESLA                          BYD                         PRECIFARM
─────                          ───                         ─────────
Integrated experience    +     Repeatable module      =    ONE Energy Module

Stackable kWh            +     Cost via repetition    =    P2 expand / Pod scale

4.3 BMS functional requirements

  • Cell voltage, temperature, current sampling ≥ 10 Hz for protection; 1 Hz for telemetry
  • SOC estimation (coulomb counting + OCV correction at rest)
  • SOH estimation (capacity fade model; cycle count)
  • Over/under-voltage, over-current, short-circuit, over-temperature, under-temperature
  • Contactor weld detect; precharge fail timeout
  • CAN heartbeat 1 s; fault latch with manual or service reset policy
  • Firmware image A/B with rollback; signed updates from Power Core only

5.3 Control logic (edge)

Priority order (local, deterministic):

  1. Safety interlocks and emergency stop
  2. Module fault aggregation — reduce or shut down
  3. Customer backup reserve floor (e.g. 20% SOC unless grid down)
  4. PAYGO credit gate (if instalment active)
  5. Solar self-consumption optimization
  6. Grid import limit (customer setting)
  7. Cloud advisory schedule (Energy OS)

Cloud cannot override safety or PAYGO lockout without signed service token.

7.2 Sizing method

  1. Load study — peak kW, daily kWh, backup duration, EV add-on
  2. Energy modules — round up to N × 2.56 kWh to meet kWh target + reserve
  3. Power unit — size inverter/PCS to min(peak load, grid export limit, budget)
  4. Solar — size to daily recharge of target SOC band; not oversized without export policy
  5. Thermal — rack airflow model; module spacing; Nairobi 25–35 °C roof install derating
